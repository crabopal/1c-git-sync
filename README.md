# 1C Git Sync

Windows-приложение на PowerShell: выгружает конфигурацию 1С в XML и отправляет её в Git.

## Скачать

Готовый архив программы лежит в [Releases](https://github.com/crabopal/1c-git-sync/releases/latest):

https://github.com/crabopal/1c-git-sync/releases/latest/download/1c-git-sync.zip

Git на клиентском компьютере не нужен: в архиве уже есть `PortableGit-64-bit.7z.exe`. Распакуйте ZIP и запустите `1C Git Sync.exe` или `run.bat`. При первом запуске портативный Git распакуется в `workdir`.

Кнопка **Обновить** внизу боковой колонки проверяет [Releases](https://github.com/crabopal/1c-git-sync/releases/latest), скачивает новый zip и перезапускает программу. Каталог `workdir` при этом не трогается. Скрипт, `run.bat`, иконка и PortableGit переносятся в папки `src` и `redist`; `1C Git Sync.exe` остаётся в корне.

Раздел **Packages** на GitHub для этого не используется: там публикуют npm, NuGet и Docker-образы. Архив приложения — это **Releases**.

## Запуск

1. Распакуйте архив из Releases (рядом со скриптом должен лежать `PortableGit-64-bit.7z.exe`).
2. Запустите `1C Git Sync.exe` или `run.bat`.

Нужна установленная платформа 1С (`1cv8.exe`).

## Действия

Слева три раздела, журнал открыт внизу окна:

- **Выгрузка** — состав и режим. «Выгрузить в Git» выгружает отмеченное и отправляет в Git. «Только Git» — индексация, commit и push. «Только push» — только уже созданные коммиты.
- **Загрузка** — что подставлять в базу. «Загрузить в 1С» приводит локальную копию к `origin` и загружает файлы в базу. «Обновить из Git» только подтягивает новые коммиты ветки из удалённого репозитория и в 1С ничего не загружает. Если в клоне есть локальные изменения или неотправленные коммиты, а на `origin` появились новые, программа спросит, приводить ли ветку к `origin`.
  Блок «Сборка .cfe» и кнопка «Собрать .cfe» собирают `.cfe` из файлов расширений в папке `Extensions` репозитория: для каждого расширения создаётся временная пустая файловая база, в неё загружаются файлы, расширение сохраняется в `.cfe`, база удаляется. Флажок «Сначала обновить из Git» перед сборкой подтягивает ветку; «Выбрать расширения вручную» открывает окно выбора (иначе берутся все, кроме расширений с префиксом исключения). Файлы кладутся в `workdir\cfe` с именем `Имя_ветка_дата-время.cfe`, прежние сборки того же расширения и ветки удаляются, после сборки открывается Проводник. Для сборки используется `ibcmd.exe` из папки выбранной платформы (клиентская лицензия 1С не нужна), базы из списка не затрагиваются. Готовый файл удобно использовать в «Сравнение/объединение» конфигуратора.
- **Настройки** — база 1С, пользователь, репозиторий и ветка. «Начать с чистого клона» удаляет локальную копию и клонирует репозиторий заново.

Настройки (кроме пароля 1С) сохраняются в `workdir/config.json`. Каталог `workdir` в репозиторий не входит.
